# セッション引き継ぎ (Handoff)

会話を別の新セッションへ渡すための、コピペで使える引き継ぎプロンプトを生成する。

## 起動時の振る舞い

- **ユーザー明示時**（「引き継ぎ」等の発言）: 確認なしで Step 1 へ進む
- **自動検出時**（精度低下兆候を検出）: 「ハンドオフした方が良さそうです。引き継ぎプロンプトを生成しますか？」と一度だけ確認してから進む

## Step 1: wrap-up 連携判断

以下を確認:
- `git status -u` で未コミット変更があるか
- 会話中に「プロジェクト固有の発見」「ハマりポイント」「ユーザー好みの新パターン」など、メモリに残すべき知見があったか

**いずれかが Yes** → 先に `wrap-up` スキルを呼び出して永続化を済ませてから Step 2 へ。
**両方 No** → wrap-up はスキップして直接 Step 2 へ。

判断結果（呼ぶ／呼ばない）を一行でユーザーに伝える。

## Step 2: 引き継ぎ情報の抽出

以下のみを抽出する:

1. **目標** — ユーザーが本来達成したい最終ゴール（一文）
2. **現在地** — 最後に正しく動いている状態 / 最後にうまくいった地点
3. **次のアクション** — 新セッションが最初にやるべき具体的な作業
4. **参照** — 関連ファイルパス（行番号含む）、メモリファイル名、直近コミットハッシュ

## Step 3: 含めないもの（ノイズフィルタ）

引き継ぎプロンプトに**絶対に入れない**:

- 後戻りした試行錯誤（途中で別アプローチに変えた経緯）
- 採用しなかった調査結果・検討した代替案
- 会話の経緯や時系列のニュアンス
- 「~について考えました」系の思考プロセス
- 「念のため」「参考までに」と前置きしたくなる情報

判断基準: **「新セッションがこれを読んで最初の一手を打てる最小情報」かどうか**。一行ずつ削っても新セッションが動けるなら削る。

## Step 4: プロンプト生成

以下のフォーマット**そのまま**を1つのコードブロックで提示する。ユーザーはコピーして新セッションの最初のメッセージに貼る。

```
## 引き継ぎ

### 目標
（一文）

### 現在地
- （最後に動いている状態を2-4行）

### 次のアクション
- （具体的な作業を1-3項目）

### 参照
- ファイル: `path/to/file.rb:42`
- メモリ: [[memory_file_name]]
- 直近コミット: `abc1234`
```

## Step 5: 提示後の自己チェック

提示前に自問:
- 一行ずつ削除しても新セッションが動けるか？ → 動けるなら削る
- 「念のため」と書きたくなった行はないか？ → あれば削る
- 試行錯誤の痕跡が残っていないか？ → 残っていれば削る
